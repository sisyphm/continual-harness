## 1. North Star

Build a **plausible generative pipeline that models the whole of Pokémon Emerald from game start to the first badge** (Stone Badge, Rustboro Gym) — i.e. a learned model you can drive with actions and that renders a coherent, playable-looking game over that whole span.

## 2. The Core Idea: a heuristic ↔ network spectrum

The research is framed as a single axis between two extremes:

```
100% HEURISTIC                                                      100% NETWORK
(ground truth)                                                      (pure learning)
   |————————————————————————————————————————————————————————————————————|
 ROM / emulator         ... we want to push the operating point ...    video diffusion
 (the game itself)          as far right as still works  ----►          w/ only diffusion loss,
 perfect GT renderer                                                    no privileged conditioning
                                                                        (KNOWN to fail)
```

- **Left end — 100% heuristic / 0% network:** the **game ROM/emulator itself**. It is a perfect, 100%-ground-truth pipeline. No learning involved.
- **Right end — 100% network / 0% heuristic:** a video diffusion model trained with **only diffusion loss**, no heuristic logic and no privileged conditioning. We are confident this **fails** (no global/world consistency, no long-horizon memory).
- **Goal:** move our model's operating point **from the heuristic end toward the network end as far as we can** while the pipeline stays plausible. Equivalently: **expand the borderline of what a video diffusion model can carry on its own.**

**Why this is a tractable / interesting research setup:** because the ROM gives us **100% ground truth for free**, every intermediate operating point is fully supervisable and evaluable. We can extract *any* subset of the true game state as conditioning, render the exact GT frames, and measure precisely how much the network can reconstruct/predict when we take heuristic crutches away. A clean experimental ladder with perfect labels.

## 3. Strategy: the conditioning-reduction ladder

We move rightward by **progressively removing privileged conditioning** (the heuristic state we hand the model). Each rung forces the network to internalize more of the game's dynamics in its own temporal latent memory. Rungs (A→Z = more network):

- **Rung A — Neural renderer (max conditioning).** Condition the diffusion model on the **full actual game memory** each step. The network's only job is **memory → pixels** rendering; all "world logic" stays heuristic. *(Coworker's first proposed step.)*
- **Rung B — Reduced structured state.** Condition only on a compressed state: **whole map (tilemap) + player coordinate + party status** (+ key flags). The network must now infer rendering details and any dynamics *not* in the reduced state. *(Coworker's second proposed step.)*
- **Rungs C … — Progressive reduction.** Strip fields further, each removal pushing state-tracking into the network:
  - drop the explicit map → model must **remember** the map from history;
  - drop coordinates → model must **self-localize** from visual history;
  - drop party/flags → model must track progression itself; … etc.
- **Rung Z — Pure network (the asymptote).** Action-conditioned (or unconditioned) autoregressive diffusion, diffusion loss only. Known failure — the right wall we are pressing against.

The **"borderline"** we are expanding = the **furthest-right rung that still produces a plausible whole-game model**. The research output is *how far right we got* and *what made the next rung break*.

> Operating-point update (2026-06-10): the full-modality model trains at **Rung A′** — *identity-based
> symbolic conditioning* (WHAT is on screen: metatile/sprite/species/char IDs, layout, logic state —
> never HOW it looks; all appearance learned). A′ sits between A (raw PPU, near-copyable) and B
> (reduced state): faithful enough to anchor the ladder, learning-based enough that rendering is real
> learning. The visual-effect tail (move animations, rustle, reflections) is a *declared learned tail*
> carried by action+history. Reduced rungs are additionally trained-in via condition-group dropout
> masks (one model spans rungs). Full design: `WORLD_MODEL_PLAN_RUNG_A_PRIME.md`.

> Scope note (updated 2026-06-08): **Model A (Rung A, full PPU condition) targets the FULL game** — overworld *and* interactions (battles, menus, dialogues, cutscenes). This is tractable precisely because full conditioning makes the network a pure renderer: it never decides game logic (the ROM/condition supplies it), it only paints the given PPU state → pixels, which is the same deterministic mapping for any screen. Exploration-only is **not** a Model-A constraint; it becomes relevant only for the *reduced* rungs / pure-network end, where un-conditioned battles/menus get hard. ⇒ Data: record continuously through everything (no battle exclusion at Rung A); the Heatz storyline run is the source of event/battle/dialogue frames, the coverage tours the source of overworld frames — both in the same RGB+action+full-PPU format. Caveat: the software-renderer *verifier* currently covers only overworld (mode-0/4bpp); battle/menu frames (256-color, affine, window, blend) need it extended to keep the pixel-perfect completeness guarantee there.

## 4. Phases & milestones (proposed)

- **Phase 0 — Data infrastructure.** Collectors that produce GT (frame, action, game-state) data start→first badge, in shapes the model needs. *(Largely built for the abstract/graph side; continuous-rollout collector pending — see Status.)*
- **Phase 1 — Rung A baseline (neural renderer).** Autoregressive video diffusion, **exploration-only, 30fps**, fully conditioned on game memory. Validate the diffusion stack and that full conditioning yields a faithful renderer. **← current baseline target.**
- **Phase 2 — Rung B.** Reduce to map + coordinate + party status; measure the fidelity/coherence gap vs Rung A.
- **Phase 3+ — Progressive reduction** down the ladder, mapping where the borderline breaks.

## 5. Evaluation (proposed, per rung)

Because GT is exact, each rung can be scored on:
- **Short-horizon fidelity** vs GT frames (PSNR / SSIM / LPIPS).
- **Long-horizon coherence / drift** under autoregressive rollout.
- **Spatial/map consistency** (does the world stay geometrically stable as you revisit tiles?).
- **Action-following accuracy** (does pressing UP actually move up?).
- **Playability** (qualitative: does it look/behave like the game over the full span?).

**Built (data infra):**
- **Storyline pipeline** (`collection/collect_events.py`): Heatz speedruns start→first badge, one GT checkpoint per story flag. Validated end-to-end (Stone Badge, 3 runs).
- **Exhaustive transition explorer** (`collection/collect_explore.py` + `collect_explore_all.py`): BFS over every tile×facing×action per flag's map. - GT state extraction exists (`read_compact_state`, comprehensive state, map buffers) — the conditioning source for the renderer rungs.

**Known gap (blocks Phase 1):** the BFS explorer is a **star fan-out** (each action tried from a state-restore) → ~2.5 frames/transition, teleporting clips. **Wrong shape for autoregressive video diffusion.** Post-hoc stitching of per-tile clips injects pervasive seam artifacts (idle-pause rhythm; ambient-animation phase jumps; NPC teleports from frozen save-states), and at 30fps ~every training window crosses a seam. → Need a **continuous-rollout collector**: plan a path from the BFS graph, then **re-walk it in the emulator continuously (no restores) @30fps**, fleeing+excluding battles ("stitch in the emulator"). Rollout policy (coverage-guided tour / random walk / hybrid) — **decision pending**.
